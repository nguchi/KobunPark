## 1. エグゼクティブサマリー

KobunParkは、LaTeX、JSON、URLコンポーネント、正規表現などの技術的な構文を、貼り付け、検証、変換、プレビュー、再コピーできるローカルファーストの個人用ユーティリティである。

主目的は、多機能な統合開発環境を作ることではない。日常的に繰り返す小さな「構文の確認・整形・変換」を数秒で終わらせ、検索、Webサービスへの貼り付け、手作業による修正を減らすことである。

開発と利用の中心はM3 MacBook Proとし、Swift・SwiftUIによるmacOS版を最初に完成させる。コア機能が安定した後にiPadOS、iOSへ展開する。初版ではWindows対応、クラウド同期、AI機能を対象外とする。

## 2. 背景

利用者は、ソフトウェア開発、IT運用、セキュリティ、Excel・VBA、Power Query、ログ解析、数学学習など、複数の技術領域を横断している。その過程では、次のような短時間だが頻度の高い作業が繰り返し発生する。

- LaTeX構文を作成し、表示結果を確認する
- JSONを整形し、構文エラーを探す
- 正規表現の一致箇所や置換結果を事前確認する
- 表形式データや各種構文を別形式へ変換する
- 変換結果を別のアプリケーションへコピーする

個別のWebサービスや大型エディタでも対応できるが、起動、入力、情報送信、画面移動の負担がある。特に業務データやクリップボードには機密情報が含まれる可能性があり、外部サービスへの貼り付けを前提としない道具が必要である。

## 3. 解決する課題

### 3.1 中心課題

構文の整形、検証、プレビュー、変換が複数のツールに分散し、単純作業のたびに操作方法を切り替える必要がある。

### 3.2 付随課題

- Webツールへ貼り付ける際の情報漏えいリスク
- エラー箇所が分かりにくく、修正に時間がかかる
- 入力形式ごとに異なるツールを探す手間
- iPhoneやiPadで取得した文字列をMacで再処理する手間
- 汎用ツールの多機能さによる操作の複雑化

## 4. プロダクトビジョン

「構文を貼ると、正しく理解できる形に整い、必要な形式ですぐ持ち出せる場所」を作る。

KobunParkという名称には、複数の構文ツールを一か所に集め、必要な機能を気軽に利用できる“公園”のような場にする意図を持たせる。ただし、名称を理由に機能を無制限に増やさない。

## 5. 目標

優先順位順の目標は次のとおりである。

1. 日常の構文処理を、原則として貼り付けから数操作で完了させる
2. クリップボードや入力内容を外部へ送信せず処理できるようにする
3. 不正な入力を黙って変更せず、修正に役立つエラーを表示する
4. macOSで毎日使える完成度に到達してから対応端末を広げる
5. 変換ロジックを再利用可能にし、機能追加時の品質低下を防ぐ

## 7. 基本利用フロー

1. 利用者が文字列を貼り付ける
2. KobunParkがJSON、LaTeX、CSVなどの入力形式を推定する
3. 利用者が変換方法を選ぶ
4. 利用者が結果または修正可能なエラーをプレビューし、結果を明示的にコピーする

ファイルを開く操作は将来の入力手段として追加できるが、主経路は上記の`貼り付け -> 自動判定 -> 変換選択 -> プレビュー／コピー`とする。形式の自動判定は補助機能であり、利用者は判定結果を上書きできる。

## 8. MVPの範囲

### 8.1 必須機能

| 優先度 | 機能 | MVPで提供する価値 |
|---:|---|---|
| 1 | JSON整形・検証 | 読みやすい整形と構文エラーの把握 |
| 2 | URL・文字列変換 | URL、Base64、HTML、JSON文字列の安全な相互変換 |
| 3 | CSV変換 | Markdown表、HTML表、XMLへの決定論的な変換 |
| 4 | LaTeX入力・ローカルプレビュー | 数式構文と表示結果の即時確認 |
| 5 | 正規表現テスター | 一致箇所と置換結果の事前確認 |
| 6 | コピー／ペーストとショートカット | Mac上での反復作業を短縮 |

### 8.2 MVPの品質要件

- macOSで安定して起動・操作できる
- 基本機能はインターネット接続なしで動作する
- 不正な入力では、可能な範囲で行・列を含むエラーを示す
- 元の入力を利用者の明示操作なしに破壊しない
- 利用者の明示操作なしにクリップボードを書き換えない
- 入力内容と履歴を初期設定では永続保存しない
- 日本語の画面表示を基本とする
- キーボード中心でも主要操作を完了できる
- 入力、処理、全クリアを取り消し・やり直しできる
- JSON、URL・文字列、CSV、LaTeX、正規表現それぞれに、代表的な構文を挿入できる入力補助ボタンを用意する
- 入力補助はカーソル位置と選択範囲を尊重し、通常の入力と同様にUndo／Redoできる

### 8.3 具体的な変換機能の実装状況と将来計画

| 入力・機能分類 | 現在の実装 | 将来計画 |
|---|---|---|
| LaTeX | 数式プレビュー | Unicode表現、MathMLへの変換 |
| JSON | 整形、圧縮、検証 | YAML、XMLへの変換 |
| CSV | Markdown表、HTML表、XMLへの変換 | 実利用後に再評価 |
| 正規表現 | 一致箇所表示、複数行対応、置換結果の事前確認 | 実利用後に再評価 |
| URL・文字列 | URL、Base64、HTML、JSON文字列の変換 | 実利用後に再評価 |

この表はプロダクト全体の計画を記録するもので、現在のMVP実装範囲を一度に拡大するものではない。MVPの安定化を優先し、後続機能は独立した決定論的変換とテストを伴って段階的に追加する。

## 12. データ・プライバシー方針

- クリップボード、開いたファイル、ログ、保存候補は機密情報として扱う
- 入力内容を既定でネットワーク送信しない
- 入力内容を生のままログへ出力しない
- クリップボード履歴を自動収集しない
- 同期を将来実装する場合も、利用者が明示保存したデータだけを対象とする
- APIキーや認証情報が必要になった場合は、ソースコードや一般設定ファイルへ保存しない
- クラウド処理を追加する場合は、送信先と送信内容を実行前に利用者へ明示する

## 13. 成功指標

初期段階では利用者が一人であるため、ダウンロード数ではなく実利用で評価する。

### 13.1 MVP完成条件

- JSON、URL・文字列、CSV、LaTeX、正規表現の5ツールがmacOS上で一つのアプリとして動く
- 各変換処理に正常系、異常系、空入力、日本語・Unicodeのテストがある
- 中核機能がオフラインで動作する
- 入力内容が意図せず保存・送信・ログ出力されない
- 主要フローをキーボードで操作できる

### 13.2 利用価値の判定

完成後2週間、自分で使用し、次を記録する。

- 機能ごとの利用回数
- 一回の作業に要した時間
- 代替ツールへ戻った回数と理由
- 誤変換、クラッシュ、分かりにくいエラーの件数
- 欲しくなった追加機能と、その発生回数

原則として、2週間で3回以上必要になった追加機能を優先候補とする。一度しか発生しない用途のために中核設計を複雑化しない。

## 15. 主要リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 機能を増やしすぎる | 初版が完成しない | MVP外機能を明示し、実利用回数で追加判断する |
| UIと変換処理が密結合になる | テストと他端末展開が困難 | コアロジックをSwiftUI Viewから分離する |
| Web表示部品がオンライン依存になる | オフライン要件を満たさない | 必要資産をアプリへ同梱し、通信なしで検証する |
| クリップボード情報が漏れる | セキュリティ事故 | 自動収集、外部送信、生ログ出力を禁止する |
| Apple全端末を同時開発する | 品質低下と工数増大 | macOSを完成させてからiPadOS、iOSへ展開する |
| 外部ライブラリが増える | 更新・ライセンス管理負担 | 標準機能を優先し、依存追加を事前評価する |
